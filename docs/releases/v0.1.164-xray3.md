# Sub2API Xray v0.1.164-xray3 Fixes and Updates

Release date: 2026-07-25

## Upstream synchronization

- Synchronized features and fixes from upstream versions `v0.1.162` through `v0.1.164`.
- Added composite groups that route models to linked subgroups across different platforms.
- Added group-level OpenAI reasoning policy controls.
- Added automatic official usage synchronization for Ollama Cloud accounts.
- Added Grok `/responses/compact`, tool caching, and related compatibility improvements.
- Added Redis ACL username support.
- Added configurable client IP modes, trusted proxies, and custom client IP headers.
- Moved asynchronous image object-storage settings into the administration interface with immediate activation.
- Added GitHub Token support for update checks.
- Added Alipay mobile deep-link support.

## Proxy and subscription compatibility

- Improved parsing compatibility for Clash, Base64 subscriptions, and common node links.
- Preserved and converted WebSocket, gRPC, HTTPUpgrade, XHTTP, and SplitHTTP parameters for VMess, VLESS, and Trojan nodes.
- Added Xray KCP/mKCP settings, traffic disguises, seed, capacity, and buffer parameters.
- Improved VMess ALPN, TLS, and compatibility parameter handling.
- Added Shadowsocks support for `v2ray-plugin`, `simple-obfs`, and Clash `obfs` conversion.
- Standardized SOCKS nodes on `socks5h` so DNS resolution is performed by the proxy.
- Return clear errors for HTTP/H2 and QUIC transports removed by current Xray releases instead of generating invalid configurations.
- Preserve nested path, Host, ServiceName, Reality, and XHTTP parameters during subscription synchronization.

## Xray and sing-box

- Fixed accounts bound to sing-box nodes failing with `unsupported proxy scheme "sing-box"` despite appearing healthy.
- Account traffic now receives a concrete local SOCKS URL that can be used by the HTTP client.
- Added idle instance reclamation for Xray and sing-box runtimes, with a default idle timeout of 15 minutes.
- Fixed repeated proxy tests eventually failing with `sing-box runtime per-user instance limit reached (16)`.
- Connection tests now use isolated short-lived runtime instances that are released after success, failure, or cancellation.
- Runtime startup failures now return explicit errors instead of being reported as unsupported proxy schemes.
- Improved TLS certificate pinning and compatibility with current Xray versions.

## IP Management and My Proxies

- Automatically run one quality check after subscription nodes are created or updated.
- Administrator IP Management and user My Proxies now test connections through the actual proxy runtime.
- A proxy with working base connectivity but an unavailable individual probe target is marked as a warning instead of completely failed.
- Added a quality-engine version marker so legacy cached results cannot overwrite current results.
- Improved storage and display of proxy latency, quality state, and connection failures.

## Account and proxy permissions

- Administrators can select and use every proxy resource from Account Management.
- Regular users remain limited to their own proxies and explicitly public proxies.
- Database constraints now support administrator-wide proxy access without weakening user resource isolation.
- Fixed inconsistencies between selected account proxies and their effective runtime state.

## Online updates and Docker

- Fixed `internal error` failures when the non-root Docker user performs an online update.
- Made the application directory writable by the runtime user so update binaries can be replaced atomically.
- Extended the GitHub Release download timeout to 45 minutes.
- Extended update and rollback request timeouts to 50 minutes for slower networks.
- Added Xray and sing-box idle-reclamation settings to Docker images.

## Other fixes

- Fixed OpenAI OAuth request input normalization.
- Fixed delayed isolation of failed proxies after OpenAI streaming disconnects.
- Improved handling of Grok 402 responses, policy-related 403 responses, and quota state.
- Improved SSE, Responses, Codex, and Anthropic gateway compatibility.
- Fixed possible loss of buffered usage and billing records during graceful shutdown.
- Improved scheduling, channel monitoring, cache billing, and model pricing matching.
- Fixed partial API Key updates potentially clearing IP allowlists or blocklists.
- Improved mobile layouts and scrolling in Account Management, Operations Monitoring, and other pages.
